# Аудит выбранных правил CIS Debian 13 v1.1.0

Один запускаемый Bash-файл `audit-cis-debian13.sh`. Внутри встроен Python 3
(только стандартная библиотека) для разбора конфигураций, JSON и безопасного HTML.
Это не реализация исключительно на Bash. Дополнительные pip-пакеты не нужны.

Основание: предоставленный CIS Debian Linux 13 Benchmark v1.1.0 от 26.08.2026.
Срез https://github.com/tarakanus10k/ansible-hardening.git:
2679b81f1659b58b2f0ca1bc61ec3fb767f55052.
Номера страниц в отчёте — печатные номера PDF.
Независимая учебная реализация 18 проверок, не официальный сканер/сертификация CIS.
Новые правила репозитория автоматически не добавляются. Все 18 проверяются независимо
от переключателей Ansible. /tmp и /dev/shm в этот срез репозитория не входят.

## Требования

Debian 13, root через sudo, Bash, Python 3. Используются штатные команды
sshd, dpkg-query, apt-cache, systemctl, auditctl. Отсутствие проверяемого пакета
или команды не скрывается: соответствующие проверки возвращают false с причиной.
Для auditd предполагается 64-битная Debian amd64/arm64, как в правилах стенда.

Скрипт не меняет настройки, не загружает правила, не перезапускает службы,
не пробует пароли и не делает apt update. Запись — только каталог отчёта.
Для проверки актуальности PAM заранее обновите метаданные отдельно:

```bash
sudo apt-get update
```

Без этого проверка 5.3.1.1 отражает только состояние локального кэша APT.

## Запуск на сервере

```bash
sudo bash audit-cis-debian13.sh --output-dir ./audit-before
# Примените ваш Ansible playbook, затем:
sudo bash audit-cis-debian13.sh --output-dir ./audit-after
```

Каталог отчёта должен быть новым; родительский каталог должен существовать.
Ранее созданные отчёты не перезаписываются. Существующий каталог или ссылка
приводит к ошибке. Отчёты создаются с закрытыми правами: каталог 0700, файлы 0600.

Результаты:
- `report.html`: автономный HTML, фильтры true/false, причины и номера страниц;
- `report.json`: настоящие JSON boolean в поле result, статус и доказательства;
- stdout: номер правила, true/false и статус (TSV).

Коды завершения: 0 — все 18 true; 1 — хотя бы один false; 2 — ошибка запуска.
Код 1 — нормальный результат аудита, а не отсутствие отчёта.

## Удалённый запуск по SSH с автоматическим скачиванием

Запускайте на исходной машине (Linux/macOS с Bash, Python 3, OpenSSH ssh/scp),
без локального sudo:

```bash
bash audit-cis-debian13.sh --remote USER@HOST --output-dir ./audit-after
```

Можно использовать alias из ~/.ssh/config:

```bash
bash audit-cis-debian13.sh --remote debian-srv --output-dir ./audit-before
```

Нестандартный порт и отдельный ключ:

```bash
bash audit-cis-debian13.sh --remote USER@HOST --port 2222 \
  --identity ~/.ssh/id_ed25519 --output-dir ./audit-after
```

Скрипт загрузит свою копию во временный каталог сервера, выполнит аудит через
sudo (при root-подключении — напрямую), передаст владельца отчётов SSH-пользователю
и автоматически скачает report.html и report.json в **локальный** каталог.
Откройте ./audit-after/report.html на машине, с которой запустили команду.

Пароль sudo вводится интерактивно в терминале; NOPASSWD не требуется. Используйте
обычный терминал: перенаправление stdin может помешать запросу sudo. Пароли не
сохраняются. SSH host key проверяется штатно; параметры ~/.ssh/config сохраняются.

Если аудит возвращает 1 (есть false), файлы всё равно скачиваются. После успешной
передачи удаляются только созданные этим запуском файлы и временный каталог.
При сбое файлы остаются на сервере; путь показывается для восстановления.
Неполный локальный каталог после ошибки сохраняется; повторите запуск с новым
--output-dir. При SSH/скачивании ошибка запуска завершается кодом 2.

Сам аудит не меняет конфигурацию сервера. Удалённый режим дополнительно создаёт
временные файлы, меняет владельца собственных отчётов и удаляет их после скачивания.
Не запускайте загруженный из недоверенного источника скрипт через sudo.

Последние четыре правила требуют syscall-правил always,exit с perm, включающим
w и a, как в PDF, одновременно в auditctl -l и /etc/audit/rules.d/*.rules.
Порядок полей/wa-aw и необязательное -S all не влияют на результат.
Устаревшие -w правила не принимаются. Дополнительные ограничивающие фильтры
(например auid>=1000) не принимаются как достаточное покрытие всех изменений.
Ключ identity/scope не обязателен для PASS: раздел Audit требует наличие
покрытия операций, ключи приведены в примерах. Проверяется включённый аудит ядра.
Наличие подавляющих never-правил или сложных удалений требует ручного разбора.
При отсутствии arch допускается правило всех архитектур; b32-only не достаточно
для выбранного 64-битного стенда. Поддержка всех эквивалентных вариантов audit rules
не заявляется; нестандартная эквивалентная конфигурация может получить false.

## Как читать true/false

- true / PASS: выбранная статическая проверка успешно выполнена.
- false / FAIL: условие не выполнено.
- false / ERROR / REVIEW: ошибка команды/чтения либо сложная конфигурация,
  которую автоматическая проверка не может подтвердить. Это НЕ доказанная
  уязвимость; сначала прочитайте причину в отчёте.

Скрипт намеренно не приравнивает пустой вывод после ошибки к успешной проверке.
Он не читает содержимое /etc/shadow и не сохраняет хеши паролей.

## Границы метода

1. sshd -T читает эффективную конфигурацию на диске, включая Include, но не
   позволяет получить настройки из памяти уже работающего sshd. Успешная
   проверка не доказывает выполнение reload. Проверка удалённого входа —
   отдельный функциональный эксперимент.
2. При Match четыре проверки параметров SSH получают консервативный false
   с ERROR / REVIEW. Дополнительные контексты можно исследовать через:
   `--ssh-context 'user=testuser,host=client,addr=192.0.2.10'`.
   Это не снимает необходимость проверить все применимые Match-ветви.
3. PAM проверяется по common-* из PDF; сложные пользовательские сервисные
   стеки, порядок переходов и фактическая блокировка входа требуют отдельного
   теста. Наличие нужных строк не доказывает корректность произвольной PAM-логики.
   Для deny/unlock_time дополнительно требуется наличие pam_faillock;
   неоднозначные дубли и альтернативное conf= не считаются успешными.
4. Аудит auditd не создаёт контрольные изменения аккаунтов и не доказывает
   доставку события на диск. Это проверка правил и состояния ядра/службы.
5. Проверки прав используют inode владельца/группы и mode; расширенные механизмы
   безопасности и символьные ссылки не являются отдельными контролями этого набора.
6. «CIS пройден» не означает точное совпадение с Ansible-переменной: deny=5
   проходит CIS, хотя роль устанавливает deny=3. Это проверка CIS, не diff роли.
7. Скрипт проверяет состояние в момент запуска. Последовательные чтения
   конфигурации не являются атомарным снимком.

## Проверка самого скрипта

```bash
bash -n audit-cis-debian13.sh
python3 test_audit.py
```

21 локальный unit-тест проходят: границы PAM, конфликтующие аргументы,
проверки присутствия модулей, разбор auditd, неполные правила, SSH Match,
экранирование HTML, скачивание при кодах 0/1 и защита пути вывода. Это проверки на искусственных данных; интеграционный
запуск на Debian 13/вашем сервере не выполнен. Отчёты с результатами сервера
появятся только после запуска вами.


## Исправление ложных FAIL auditd (версия 3)

- Поддержан вывод auditctl -l с развёрнутым списком -S. Скрипт получает ожидаемое
  множество вызовов perm=wa для родной b64-архитектуры из установленной
  libaudit.so.1 через ctypes. Создание правила выполняется только в памяти:
  audit-сокет не открывается, правила в ядро не отправляются.
- Неполный произвольный список -S не считается достаточным: он должен содержать
  всё вычисленное множество. Если библиотека не умеет раскрывать perm, проверка
  развёрнутой формы остаётся false с диагностикой; отсутствие -S и -S all по-прежнему
  поддерживаются. libaudit1 уже является зависимостью auditd.
- Учтено поведение augenrules: отдельная строка -D переносится в начало, поэтому
  -D в позднем файле не отменяет ранее прочитанные правила. Удаления с аргументами
  всё ещё требуют ручной проверки.
- При FAIL отчёт теперь показывает найденные строки-кандидаты и ожидаемые syscall.

Регрессии проверены 21 unit-тестом. Дополнительно использована библиотека из
официального Debian-пакета libaudit1 4.0.2-2+deb13u1 amd64: развёрнутый список
из снимка принят, список с удалённым openat2 отвергнут. Пакет распакован отдельно;
библиотека системы не заменялась. Это не запуск аудита на удалённом сервере.
