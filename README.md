# Харденинг OS Linux с помощью ansible

Linux широко распространен в серверной инфраструктуре и каждая машина нуждается в настройке. Ручная конфигурация может привести к уязвимостям системы, а при большом парке машин ручная настройка может занять огромные ресурсы. Для автоматизации данной задачи используют инструмент ansible.

Ansible - это инструмент автоматизации управления конфигурациями от Red Hat. Он позволяет автоматизировать удаленные задачи, обеспечивать надежную защиту OS сервера и значительно снижая поверхность для атак. При этом достигается высокая эффективность, скорость и надежность, а также минимизируются трудозатраты и риск человеческих ошибок.

Ansible использует простые, понятные человеку скрипты, называемые плейбуками, для автоматизации ваших задач. В плейбуке указывается желаемое состояние локальной или удаленной системы. Ansible гарантирует, что система останется в этом состоянии.

Для харденинга OS Linux будет использоваться связка Ansible и CIS Benchmarks.

CIS Benchmarks - это международно признанные стандарты и пошаговые руководства по безопасной настройки программного обеспечения, операционных систем, облачных платформ и сетевого оборудования. Назначением является закрыть уязвимости и минимизировать "поверхность атаки". Каждый бечмарк имеет 2 конфигурационных профиля:

- Level 1 - элементы в этом профиле предназначены для:
	- быть практичным и разумным;
	- обеспечивать явную пользу для безопасности;
	- не ограничивать функциональность технологии сверх приемлемого уровня.

- Level 2 - данный профиль расширяет level 1. Элементы этого профиля обладают одной или несколькими из следующих характеристик:
	- предназначены для среды или случаем использования, где безопасность имеет первостепенное значение;
	- служат мерой глубокой защиты;
	- могут негативно повлиять на функциональность или производительность технологии.
## Подготовка

Используемые инструменты и программы:
- Среда выполнения: WSL с дистрибутивом Debian-based, Виртуальная машина с дистрибутивом Debian-based;
- Утилиты: ansible;
- Стандарты: CIS benchmarks.

- ### 1. Ansible

Подготовка к установке ansible (WSL):
```bash
sudo apt update

# Установка pipx
sudo apt install pipx
# Добавление pipx в переменные окружения

pipx ensurepath
```

Установка ansible (WSL):
```bash
pipx install --include-deps ansible
```


- ### 2. ВМ с дистрибутивом Debian-based

В качестве дистрибутива будет использоваться [debian актуальной версии 13 ("Trixie")](https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/debian-13.7.0-amd64-netinst.iso)

Установка:
1. Подготовка к установке (vmware)
	1. Создаем новую машину;
	2. Кол-во процессоров: 2
	3. Кол-во оперативной памяти: 2Гб
	4. Кол-во памяти: 30Гб
	5. Тип виртуального адаптера: bridged adapter
	6. Подключение установочного образа
2. Установка системы (vm)
	1. Имя машины (hostname): lin-deb-server
	2. Имя пользователя: srvadmin
	3. Разметка диска: Ручной режим
	4. Загрузочный раздел: `/boot/efi` размером 512Мб
	5. Выделение неразмеченного пространства для конфигурации LVM

После установки:
1. Обновление системы:
```bash
# обновление
sudo apt update
sudo apt upgrade
```
2. Узнать ip:
```bash
ip a
```
Примечание: Если при установке системы был задан пароль для root пользователя, то пакет `sudo` будет отсутствовать и его нужно будет скачать и настроить (от пользователя root с помощью команды `su`)

- ### 3. Настройка SSH

Создание ключей (WSL):
```bash
# установка openssh-server
sudo apt install openssh-server

# герерация пары ключей
ssh-keygen -t ed25519 -C "ansible-control"
# путь: ~/.ssh/ed25519_ansible_key или по умолчанию
# passphrase: задать или оставить пустым

# Копирование публичного ключа на ВМ
ssh-copy-id -i ~/.ssh/ed25519_ansible_key.pub srvadmin@192.168.100.10

# проверка
ssh srvadmin@192.168.100.10
# или (если задана passphrase)
ssh -i ~/.ssh/ed25519_ansible_key srvadmin@192.168.100.10
```

- ### 4. Настройка ansible

Настройка `hosts` файла:
```ini
#hosts.ini
[linux_debian_13]
debian-srv ansible_host=192.168.100.10
```
или:
```yaml
#hosts.yml
---
all:
  children:
    linux_debian_13:
      hosts:
        debian-srv:
          ansible_host: 192.168.100.10
```

В файле `hosts.*` мы указали имя хоста и его адрес для последующего подключения.
Также создадим файл `linux_debian_13.yml` для указания дополнительных параметров для подключения:
```yml
---
ansible_user: srvadmin
ansible_ssh_private_key_file: ~/.ssh/ed25519_ansible_key
ansible_python_interpreter: /usr/bin/python3
ansible_become: true
ansible_become_method: sudo
ansible_become_pass: "{{ debian_srv_sudo_pass }}"
```
описание переменных:
- `ansible_user` - указываем имя пользователя от которого будут происходить действия;
- `ansible_ssh_private_key_file` - путь до ssh ключа для подключения;
- `ansible_python_interpreter` - какой именно исполняемый файл python использовать на удаленном хосте для работы модулей;
- `ansible_become` - используется для повышения привилегий;
- `ansible_become_method` - конкретный способ повышения привилегий;
- `ansible_become_pass` - пароль для повышения привилегий.

Для хранения пароля для повышения привилегий на удаленном хосте используется зашифрованный файл, создаваемый следующим образом:
```bash
ansible-vault create ~/your/path/vault.yml
```
При выполнении команды нужно создать пароль для данного файла. После создания пароля открывается текстовый редактор где уже можно ввести пароль для повышения привилегий:
```yml
---
debian_srv_sudo_pass: "your_password"
```

- ### 5. Создание плейбука и ролей
- #### [5.1 Создание плейбука](playbooks/README)
```yml
---
- name: Linux Debian 13 hardening
  hosts: all
  become: true

  roles:
    - ssh-hardening
    - pam-hardening
    - auditd-hardening
```
